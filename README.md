# 星网文档内容评审 Demo V1

独立交付的项目原型。复用 ClauseGraph 的条款树、预定义本体和图谱发布；按评审本体自动安排全部适用维度，各视角独立消费已有关系，生成可定位的原文意见，由用户确认采纳为修订版本。

不依赖乡村或大创项目的目录、Python 包、前端、数据库或运行记录。实现参考乡村最新远端 `feat/workflow-rural` 的 V1.6（`3fd8d8f`）中的流式交互、原文绑定和版本留存经验。

## V1 范围

- DOCX / Markdown 导入；五类文档合册按各部分分开保存逻辑文档，仍保留原 DOCX 的真实位置。
- 支持需求、设计、集成测试报告、出厂测试大纲和测试细则等独立文档组成项目。
- 维度来自 `resources/review-ontology.ttl`，当前包含需求与追踪、设计与实现、接口与数据、测试与验证、性能与质量五个独立视角。前端不让用户选择维度，数量与范围不写死在前端。
- 按本体声明的文档范围覆盖全部适用原文，较长材料分批处理。维度之间独立、最多两个请求并发，不组队或相互讨论，结果由程序汇总。
- 本体推理采用召回和沿已有关系探索，不抽取或生成新的隐含关系。
- Neo4j 中查询 ClauseGraph 的词面关联和已有类型关系，结合文档角色筛选上游依据及文档内部相关内容。文档的工程依赖不取决于文件排列顺序。
- LangGraph 编排“查询已有关系 → 一次模型内容评审 → 原文绑定”。每个批次只有一次模型请求，不自动反复调用，不额外安排模型审查或汇总。
- 主界面默认展示圆形节点组成的力导向本体知识图谱，支持拖动缩放、双击展开条款、节点和连线依据。评审动态随真实事件高亮已有路径，并支持无需模型调用的历史轨迹回放。阶段流程图保留为辅助视图。
- 简体中文流式评审分析；原文旁定位意见、展示依据、编辑后采纳、驳回及下载修订文档。
- 原始文件永不覆盖。采纳只在选中的段落或单元格应用局部替换，保留原件与历史图谱快照。

评审允许没有问题，不为了演示编造冲突。未能唯一定位的摘录保存在执行记录中，不随意绑定到某个位置，也不据此修改文档。

## 技术与目录

| 目录 | 内容 |
| --- | --- |
| `backend/starnet_review/` | 独立 FastAPI、单视角 LangGraph、ClauseGraph / Neo4j 接入与 DOCX 修订 |
| `frontend/` | 独立 React / TypeScript 界面、流式输出、本体路径与原文意见 |
| `resources/` | 同门原版软件工程类型本体、显式评审维度及文档依赖本体 |
| `tests/` | 文档分界、引用绑定、单次调用、修订位置与原件保留等离线验收 |
| `data/` | 私有文档、原件、图谱数据库、项目记录与修订，默认不入库 |
| `.env` | 本地模型和样例路径，默认不入库 |

ClauseGraph 固定依赖 [Lands54/ClauseGraph](https://github.com/Lands54/ClauseGraph) 的提交 `97dc788983c4e4a3c0e2e2bbb5f3192ac0e31f23`。`resources/software-engineering-ontology.ttl` 来自该提交的同名示例，本项目未改动其节点和关系定义。

同门领域 Profile 没有直接定义“评审维度”。新增的 `resources/review-ontology.ttl` 显式连接维度、已有领域概念、适用文档类型和标准摘录，并定义上下游文档约束；不把这部分应用建模说成同门原本已有的本体内容。已有领域关系、规则匹配、评审配置和运行使用关系在图上分别标记。

生命周期展示与证据口径见 [本体外显说明](docs/ontology-lifecycle.md)。召回、装配输入和最终意见引用是不同事件。输入清单保存真实条款、路径和标准标识及消息哈希；这些数据由程序产生，不让模型填写。

模型填写问题文字、摘录、解释和建议文本。真实文档、版本、章节、引用、修改位置和文件保存均由程序绑定，模型不填写内部 ID 或路径。严格 JSON Schema 约束返回形状；它不代表模型的语义判断一定正确，仍需用户查看依据后决定采纳。

## 安装

需要 Python 3.12+、Node 20.19+ 和本地 Neo4j Community。Neo4j 所需 Java 版本以安装的发行版要求为准。

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
npm --prefix frontend install --cache "$PWD/data/npm-cache"
cp .env.example .env
```

在 `.env` 设置模型 Key、基础地址和模型名。默认 `qwen3.8-flash`。不要提交 `.env` 和源文档。

`DEMO_DOCUMENT`、`DEMO_DOCUMENT_2` 可分别指向已提供的 DOCX 合册或包含多份 DOCX 的目录；也可直接在界面上传文件。`GJB_SOURCE_JSON` 指向所给的 GJB 438C 条款结构 JSON，程序按视角读取相关标准摘录，并保留原 PDF 页码。

## 启动

本机已配置后，可双击根目录的 `启动演示.command`。它使用本项目自己的环境启动服务并打开页面；也可运行 `.venv/bin/python scripts/start_services.py`。部署时可用 `requirements.lock.txt` 和 `frontend/package-lock.json` 固定本轮依赖。

默认使用独立端口，避免与既有项目混用：

| 入口 | 地址 |
| --- | --- |
| 页面 | http://127.0.0.1:5180 |
| 后端 | http://127.0.0.1:8010 |
| Neo4j Bolt | bolt://127.0.0.1:7689 |
| Neo4j Browser | http://127.0.0.1:7476/browser/ |

```sh
# 首次启动本地独立数据库。配置、数据库与日志均在本项目 data 中。
# 如 neo4j 不在 PATH，先设置 NEO4J_BIN=/路径/bin/neo4j
python3 scripts/start_neo4j.py

# 在一个终端启动后端
.venv/bin/python -m uvicorn starnet_review.main:app --app-dir backend --host 127.0.0.1 --port 8010

# 在另一个终端启动前端
npm --prefix frontend run dev
```

该本地数据库仅监听环回地址，默认不开启认证。如果接入已有带认证的数据库，在 `.env` 配置 `NEO4J_URI`、`NEO4J_USER`、`NEO4J_PASSWORD`，并自行启动相应服务即可。

## 演示步骤

1. 加载已提供的项目样例，或一次上传需求、设计和测试文档。
2. 在首页查看自动生成的全维度计划和批次数。原文浏览位置不影响评审范围。
3. 点击“开始项目全维度评审”才会使用模型 API 额度；实时分析按独立维度展示。
4. 默认进入“本体知识图谱”。双击概念或文档展开条款，点击关系查看来源。在“评审动态”查看或回放某次真实记录中的已有路径、输入、引用和采纳版本；“流程概览”只说明阶段。旧单章节记录明确标为历史记录，不计入新全维度完成数。
5. 点击一条意见，回到对应原文。检查上游依据和局部修改预览，可编辑后采纳或驳回。
6. 下载当前修订版。合册导入的项目下载的是完整修订合册；独立文档项目下载对应文档。
7. “执行记录”显示本次状态、耗时、模型调用次数及实际 Token 用量。

如果样例内容一致，应展示一致性分析与实际依据，无须强行生成修改意见。未提供任务书时，仅使用已提供的上游文档，不自动把任务书未上传判定为项目内容缺陷。

```sh
# 可选：用真实项目、真实 Neo4j 和替代模型检查全维度数据流，零模型 API 调用
.venv/bin/python scripts/verify_lifecycle_offline.py 项目ID
```
