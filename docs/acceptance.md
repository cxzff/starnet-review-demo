# V1 首次联调记录

日期：2026-11-10。项目与运行环境独立于乡村和大创；参考远端最新乡村 `feat/workflow-rural` 的 V1.6 实现经验。

## 范围和输入

实际导入用户提供的“06 卫星 星地测控指令调度软件”目录中五份独立 DOCX，分别识别为软件需求、软件设计、集成测试报告、出厂测试大纲和测试细则。此次未提供任务书，不据此生成任务书缺项意见。

本体采用同门 ClauseGraph 指定提交中的原版软件工程 Profile，节点与关系定义未修改。ClauseGraph 实际生成并向独立 Neo4j 发布了 253 个节点和 4,845 条关系。当前不启用内容本体生成，不产生新的隐含关系。

## 真实模型联调

测试评审智能体对集成测试报告“5.1 测控窗口核验”进行一次真实调用，采用 qwen3.8-flash。仅验收该章节，不是整个项目全量验收。

| 指标 | 结果 |
| --- | --- |
| 总耗时 | 29.91 秒，含关系查询、模型输出和意见定位 |
| 模型调用 | 1 次 |
| 输入 Token | 12,646 |
| 输出 Token | 1,474 |
| 总 Token | 14,120 |
| 原文意见 | 3 条，均定位到待审内容 |
| 已有本体路径 | 9 条，均来自 Neo4j 查询 |

首轮发现两个问题：证据摘录中包含程序展示的文档标题，未直接绑定原文；模型将一条措辞优化意见标为内容冲突。引用接口已统一为原文对象输入，并能绑定本轮记录中由程序生成的完整来源展示条目，使用原记录离线回放，三条意见分别绑定 1、2、1 处依据，没有增加模型调用。新输入还携带去重后的文档范围与状态说明。

语义判断仍需人工确认。界面支持编辑类别和修改文字；本轮将明确单位的措辞建议人工改为“改进建议”后采纳，保留原模型类别供追溯。没有把该人工修订当作模型自行判断正确的证据，也未在接口整理后追加付费调用。

- 使用实际五份 DOCX 和真实 Neo4j，替代模型走完全部 13 批次；逐项核对输入清单，原项目文件哈希不变，真实模型调用为零。结果见 `data/acceptance/lifecycle-offline.json`。
- TypeScript 检查与前端生产构建通过。
- Chrome 实际界面检查通过：自动维度展示、本体文件详情、节点拖动、候选挂接连线依据、历史输入说明、意见跳转原文、800 像素视口，以及替代流式输出期间节点不被重新挂载；没有浏览器运行错误，也未发起模型请求。结果见 `data/acceptance/lifecycle-ui.json`。
