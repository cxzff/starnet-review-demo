# 本体外显与全维度评审

本页记录2026-11-10的旧版展示与验收口径。2026-11-11已改为单文档、多视角的增量评审，分离静态规范、文档内容和运行记录，详见[当前设计](content-ontology-growth.md)。旧版的13批计划不再作为新流程。

本轮重点是让客户能够查看本体在输入、判断、引用与修订各阶段的实际作用。图谱展示持久化的定义和执行记录，不展示或推测模型内部思维链。

## 两份本体的职责

| 文件 | 来源与作用 |
| --- | --- |
| `resources/software-engineering-ontology.ttl` | 同门 ClauseGraph 原版领域 Profile，定义 32 个概念、词面匹配规则和已有概念关系。本项目没有改写其定义。它是应用型 Profile，不宣称是完整 OWL 推理机。 |
| `resources/review-ontology.ttl` | 本 Demo 新增的显式评审应用本体，声明五个独立维度、关联概念、适用文档类型、标准摘录和上下游文档约束。 |

当前维度为需求与追踪、设计与实现、接口与数据、测试与验证、性能与质量。程序从 RDF 读取，不由前端固定数量，也不让用户选一部分维度才执行。维度之间没有消息协作。长文档分批是输入处理方式，不是新增评审维度。

工程依赖在本体中显式声明：需求受任务书约束；设计受任务书和需求约束；测试计划、细则和报告逐步受对应上游文档约束。未提供任务书时不会因此推断项目本身缺少任务书。关系用于确定检索和判断范围，不代表存在关系就已满足内容要求。

## 三种图谱视图

1. **本体知识图谱（默认）**：采用力导向网络，以圆形节点展示已有概念、文档和评审维度，不按阶段排列成流程图。当前样例默认显示 42 个节点、188 条关系，包括 32 个领域概念。双击概念或文档可展开其原始条款与挂接边；点击边可查看方向、命中词、规则分数及候选/待确认状态。缩放、节点拖动和局部展开不调用模型。
2. **评审动态**：使用同一种网络视图，逐步展示真实记录中的条款、已有路径、装配输入、独立评审智能体、意见引用和用户采纳。实时模式跟随保存的召回和输入事件；用户也可选择一份历史记录回放。回放仅改变可见节点和高亮状态，不新增本体事实，不重新调用模型，也不补造事件时间。
3. **流程概览（辅助）**：保留原阶段图，用于说明“本体加载 → 条款挂接 → 节点与原文召回 → 已有关系探索 → 约束判断 → 意见引用与定位 → 采纳与版本更新”。它不再作为默认本体展示。

默认图中的文档—概念点线是折叠条款后的显示汇总，每条汇总保存对应的真实条款 ID。它不是新建的本体关系；展开后可以查看原始 `CLASSIFIED_AS` 边。已有本体关系、评审配置、文档汇总和实际使用关系有不同的颜色及线型。

“本次原文召回”不再作为图谱节点，召回块数、已有路径数、输入标准数和实际被引用的标准数统一展示在右侧统计区。章节节点同时显示所属文档名，详情保留完整文档标题。文档和标准原文属于资料层；模型输入、引用、意见、修订和历史输入清单属于运行记录，使用虚线外圈和独立的关系说明，不能与已有本体关系混为一谈。高亮不会把已有本体关系的实线改成运行记录虚线。

标准的来源与使用分为三类关系：

- **配置选取**：新评审在运行记录中保存实际使用的配置文件名、版本、哈希及维度标准声明；冻结计划已保存的配置也可追溯。图上只为该配置确实声明的标准画配置边。
- **进入输入**：标准原文来自该次保存的上下文，连接该次模型输入。这是运行使用关系，不是“标准约束项目条款”的语义关系。
- **意见实际引用**：只有意见证据已经绑定到对应标准原文，且引用摘录确实包含在保存的标准中，才连接标准与意见。分析仅提到 `M.4` 或 `N.3` 不算正式引用，也不生成引用边。

旧单章节记录未保存原配置文件版本时，显示“历史标准输入清单”及来源缺失说明，不把今天的配置补当作旧来源。当前真实历史记录保存了三条标准输入，已定位的标准引用为零；这与“模型没有读标准”不是同一结论。新增配置快照只写入运行元数据，不进入模型提示词，不增加模型调用。

布局在节点增加或用户拖动时平滑调整并逐步稳定；流式文字输出不会重新挂载节点或重置布局。回放按已保存对象所属阶段显示节点，探索阶段高亮已有类型关系，意见及修订仅在实际记录存在时出现。失败或尚未执行的后续阶段不会伪造模型输入、意见或修订节点。

图例区分已有领域本体关系、显式评审配置、文档结构/规则挂接、运行使用关系。运行边只是溯源，不回写成模型发现的新领域关系。

## 怎样区分召回与消费

| 层次 | 记录与界面含义 |
| --- | --- |
| 候选检索 | ClauseGraph 原生词面关系及文档上游范围；不把检索未命中说成全文缺失。 |
| 已有关系探索 | Neo4j 查询同一快照中最多两跳的已有类型关系及两端条款；不生成新隐含关系。 |
| 请求输入 | 保存实际待审块、召回块、路径、概念、标准标识和消息哈希；详情可展开查看真实原文与标准。 |
| 内容判断 | 保存模型实际返回的简体中文分析和意见；结构正确不代表语义一定正确。 |
| 意见引用 | 只展示原文绑定成功的引用，以及引用端点匹配的已有路径；不把全部召回原文自动标成已引用。 |
| 采纳修订 | 用户确认后在副本局部替换，保留原件、修订文件哈希和前后图谱快照。 |

旧记录没有新版输入清单或版本字段时，界面明确说明，没有补造清单、哈希或时间记录。历史图谱和意见仍指向当时的快照；采纳后的当前图谱不会冒充历史输入。

## 本轮验收边界

星地测控指令调度软件五份 DOCX 已接入真实 Neo4j：253 个原生节点、4,845 条原生边；可视化选择展示其中的结构、挂接和类型关系，不把全部词面相似边挤进画面。

当前全维度计划为五个适用维度、13 个处理批次。使用真实原文和 Neo4j、替代模型离线走完 13 批次，覆盖清单与输入清单一致，原项目记录未变，真实模型调用为零。历史章节真实评审仍可回看，但本轮没有追加付费全项目语义验收。
