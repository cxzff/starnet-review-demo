# 单文档、多维度评审与内容本体生长

日期：2026-11-11。

## 调整后的主线

按顺序导入当前文档 → 构建当前文档自己的内容本体 → 复用已保存的上游本体 → 启用多个适用视角，每个视角一个专家任务 → 保存原文意见与修订；下一份文档单独发起。

取消按14,000字符切出的维度批次。每轮只处理选定的一份文档；文档可以有多个章节、多个适用评审视角。每个视角一个任务，章节用于定位和取证，不在后台继续执行旧的多批评审。接口中的 `batches` 和 `batch_count` 暂时保留以读取历史记录；新计划分别表示单个专家任务及任务总数，`strategy` 为 `incremental_document_review`。旧批次记录不冒充新架构的完成结果。

## 三类知识和记录分开

| 数据 | 内容与来源 | 展示 |
| --- | --- | --- |
| 静态规范及类型本体 | 提供的GJB条款树、规范原文与PDF页码；同门原版类型Profile | 静态规范本体 |
| 文档内容本体 | 当前文档实际出现的对象、指标、条件、明示关系及原句；复用二路的条款类型挂接 | 文档内容本体 |
| 流程及执行记录 | `workflow-ontology.ttl`中的角色和阶段；实际模型输入、引用、意见、调用和修订 | 流程概览、运行与消费记录 |

GJB规范文字保留原样，不被项目内容覆盖。规范树展示不代表全部规范要求已经自动编译为语义公理或执行规则。二路仍采用同门的现有类型Profile和匹配规则，不能将其声称为已经完成的完整GJB语义本体。

## “生长”的含义

- 第三路接收每份文档的全文，抽取文档自己的概念和原文明示关系，名称不限于原来的32个类型。已匹配和未匹配条款都参与抽取。
- 使用现有Qwen配置，只对本轮文档的新版本做一次内容抽取；不是每个维度再抽取一次，不自动构建其余已上传文档。同一版本后续评审直接复用。
- 模型返回业务名称、关系文字及原句。程序绑定真实条款、原文块、文档版本和图谱身份；不要求模型填写内部ID。
- 只有原句可绑定的内容进入可消费图谱。无法绑定项保留在草稿记录；绑定成功仍不等于语义已经正确，图中明确标为待核查。
- 每份文档保存后即可在内容视图出现。当前文档与已保存上游的内容结果发布为Neo4j快照，各适用维度复用；发布前的本地记录不冒称已经发布到Neo4j。
- 不同文档中同名概念仍保留不同身份，不能只凭名称相同合并成同一业务对象。新内容不回写为GJB要求，也不自动增加没有原文依据的隐含边。

原始全文条款树始终保留。内容抽取可能遗漏，不能以“概念已抽取”代替“所有原文语义均已覆盖”。

## 一份文档怎样由多个视角评审

文档是本轮对象，维度是专家视角，章节和条目是资料单元，三者不混用。当前配置下：需求说明启用需求与追踪、接口与数据、性能与质量；设计说明启用设计与实现、接口与数据；测试计划/细则启用测试与验证，测试报告还启用性能与质量。适用性来自评审本体，不要求每份文档都用全部五个视角。

用户每次上传一个文件；若文件为合册，可从拆出的逻辑文档中选择本次目标。原文浏览与本次评审对象分开，查看上游章节不改变派工范围。上传下一份文档默认切换到新文档，已有本体和评审结果保留。

上游尚未建立本体时明确标注，本轮可参考已上传原文，但不自动替上游建图或重评。历史结果按当前文档版本、上游版本和配置判断是否仍适用；添加无关下游文档不会把已经完成的需求评审重置。

## 维度评审怎样消费

每个维度读取已保存的内容概念、明示关系、适用标准以及该维度的完整待审原文；适用的上游文档按已有工程依赖提供。跨文档引用和意见位置由程序绑定到实际文档，不能默认归入该维度的第一份文档。

本轮不再设置任意的字数切批门槛，也不静默截断原文。模型服务仍有输入和输出上限；若超过服务限制，记录实际失败，不自动重试或伪装为已完整评审。后续若面对超过模型容量的文档，需要单独实现可追踪的图检索式阅读，不能靠隐藏批次宣称一次读完。

## 用量和验收

建图调用、评审调用、输入/输出Token及总耗时分别记录。首次构建有额外成本，不能仅凭维度调用数减少就宣称整体必然更快。

离线检查覆盖：长文档多章节不再切批、单文档多视角、顺序上传后上游本体和旧结果保持、版本缓存、原文引用绑定、新概念及关系的原生图发布、建图与评审分别计量、多文档意见归属、未发布内容可见，以及静态规范文字不被修改。

`scripts/verify_lifecycle_offline.py`使用独立的 `offline-` 项目身份和替代模型，依次核对需求、设计、测试计划、测试细则和测试报告的多视角任务、Neo4j发布和输入覆盖，不改写原项目记录。结果保存在 `data/acceptance/content-growth-offline.json`。替代模型结果只用于验证数据流，不代表真实模型的内容抽取质量或提速结论。

本轮不自动运行付费评审，也不自动将历史样例重建为真实内容本体；用户下次点击开始评审时才实际构建。

## 本次与历史结果的展示

打开已有文档不会自动把旧意见、旧执行记录视为本次结果。未点击开始时显示“本次评审尚未开始”；没有文档内容本体时显示“原文与静态挂接”，原文可提前浏览。已保存的内容本体明确标为已保存，可复用，但不代表已经启动新评审。

旧意见与消费记录放在显式的“查看历史结果”入口。新的本次结果按服务端真实生成的cycle标识筛选，旧记录不自动补入；切换文档会清空本次显示状态。历史查看和回放不发起模型请求。
